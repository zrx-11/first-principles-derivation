# 工作流程详版

SKILL.md 里是提要，这里写各阶段的做法、判据和历次踩坑记录。执行完整任务时先读这份。

## 阶段 0：确认范围

需要锁定三件事：学什么、产物什么形态、学的人什么水平。

默认设置：单文件交互式 HTML；学习者按初二水平算，数学只学到一元二次方程和简单的相似三角形。用户没说清楚时用默认值，问超过三个问题会拖慢开工。

范围里容易忽略的一点：这个课题的边界在哪。比如"数学分析第 18 到 20 章"是明确范围，但"支持向量机"要确认是硬间隔为止，还是把核方法、软间隔、对偶都包进来。范围不定，依赖图会画歪。

## 阶段 1：逆推依赖图

对目标知识的每个概念问一句：要读懂它，得先会什么。一直问到不能再问为止。能退到的东西大概这几类：

四则运算与分数运算；大小比较和等号含义；数数、自然数、求和记号怎么来的；且、或、非、如果那么、反证；长度、面积、距离、速度、时间、排队这类生活常识。

退到位以后画一张链：根系 → 基础概念 → 领域工具 → 主干。产物开头的知识树就是这张链的可视化，节点可点击跳到对应章节。

判定补不补，只用一个标准：不补这一步，后面那一步会不会卡死。会，就补，哪怕初中生没学过矩阵、没学过极限。不会，就跳过，不要为了体系完整硬塞。比如 SVM 里不需要测度论，Transformer 里不需要复变函数，这类直接声明"本课不涉及"即可。

依赖图要落成文字，放进产物的知识树章节，同时作为后面章节顺序的依据。章节顺序基本就是依赖图的拓扑序，先出现的知识后面不再重复解释（只做一句话回指）。

## 阶段 2：正向推导

从根系往上，每一层四件套：

一句严格定义。用初中生能读的句子，术语不要嵌套术语。

一个生活类比。从 `references/intuitions.md` 里找，找不到就现场造一个，用完记得登记。

完整代数过程。每一行变化都写出来，包括"两边同除以 a""移项""代入消元"这种看起来不值一提的步骤。判断标准是：一个初二学生能不能在你的下一行之前自己写出这一行。写不出来，就加中间步骤。

数值算例。代入具体数字算一遍，最好算到最后一步得出结论。例子本身要能自洽，见阶段 4 的第二条。

这一阶段还有两条纪律。符号第一次出现时给白话解释，Σ、∀、∃、inf、lim、sgn、∇ 这些都算。每章开头标前置知识，章末标后续应用，让学习者知道这一步后面用在哪，否则会觉得是在做无用功。

推导到主干之后，还要回答一类问题：为什么这样设计。比如 SVM 为什么标签取 +1 和 -1 而不取 0 和 1，为什么间隔要归一化，Transformer 为什么要缩放 √d_k。这类问题学习者不问，但他会想，想到了没有答案就会怀疑整个体系。所以主干章节里尽量放一小段"设计动机"，用反例说明不这么设计会出什么事。

## 阶段 3：搭 HTML

### 结构

章节 id 和导航 data-target 必须一致，这是三个坐标里的两个，第三个是章节顺序数组，三处同步。历史上有过一次不一致，点了目录没反应，排查半天。

每个章节内部放自己的面包屑和上下章容器，查找时用 `chapterEl.querySelector('.breadcrumb')`，不要 getElementById。多章节页面里 id 会重复，getElementById 只命中第一个，其余章节的导航容器永远是空的。这个 bug 在 Transformer 那次漏在数学基础章节，切过去以后没有上下章按钮。

顶栏固定，放目录按钮、当前章节名、前后箭头，移动端滚动时一直可见。主内容留出顶栏高度的 padding。桌面端隐藏顶栏，改用常驻侧边栏。

目录入口得是真实按钮，绑定了 openSidebar。有过一次函数写好了但页面上没放按钮，目录永远打不开。

### 视觉

移动端优先，第一行 CSS 按 375px 写，桌面样式放进 @media (min-width: 768px)。所有容器 max-width:100%，正文 overflow-wrap:break-word。公式块 overflow-x:auto，宁可让长公式自己滚，不要让整页左右晃。

生活直觉放绿色提示框，位置在正式推导之前，先给画面再给定义。前置知识黄色左边框，后续应用绿色左边框，关键结论单独强调框。推导步骤折叠，默认收起，点击展开，嵌套一层也要能点。

### 公式

KaTeX 的 CSS、JS、auto-render 全部内联。字体也内联，把 woff2 转 base64 塞进 @font-face。只内联 CSS 和 JS 的话，file:// 下字体请求 404，控制台报错，公式字形退化。

KaTeX 0.16.9 的 npm 包里 woff2 一共二十个，约 250KB，内联后 HTML 增重约 340KB。核对文件清单时注意，这个版本里没有 KaTeX_Math-Regular、KaTeX_Symbols-*、KaTeX_Greek-*、KaTeX_SmallDelimiter-* 这些，按 404 忽略即可。替换 url 的正则要同时兼容 `url(fonts/x.woff2)` 和带引号的 `url("fonts/x.woff2")` 两种写法。

渲染时机：页面加载后遍历所有章节渲染，包括 display:none 的。完成后带重试，轮询 window.renderMathInElement 是否存在。切换章节时对目标章节重新渲染一次，同样带重试。

### 交互

用 Canvas 做可拖拽或可调参的演示，比如调 C 和 γ 看决策边界怎么动，调温度看概率分布怎么变。每个演示配说明和坐标轴标注，不要让学习者自己猜横轴是什么。

## 阶段 4：模拟差生通读

这是整套流程里最费时间的部分，也是最容易被跳过的地方。

设定一个具体的人：初二，数学成绩中等偏下，做题靠套公式，看到 Σ 会愣住，读到第二行忘了第一行在讲什么。然后以这个人的身份从头读到尾，每遇到卡壳就停下。停下的判据有四条：

这一步用到的概念前面出现过吗，出现时解释过吗。

这一步的代数变形，跟着走能不能自己补出下一行。

这个符号第一次见吗，有没有白话说清它是什么。

这个结论是只给了"是什么"，还是讲了"为什么"。

四条里任意一条为否，就要补。补的方式不一定是加字，也可以是换顺序、拆步骤、换类比、加一个数字例子。

典型的卡点，来自三个课题的实际记录：

SVM 那边，双重求和的展开需要 n=2 的数值演示；余弦定理和求根公式直接给结果会让读者断链，需要补推导；参数规范化（同一条直线有无穷组 w,b）需要用具体数字演示两套参数画出同一条线；KKT 和互补松弛要用围栏和建墙的实物类比；对偶问题为什么是最大化而不是最小化，要补"猜身高下界"的类比；VC 维要用三个点和四个点的具体摆法。

Transformer 那边，矩阵转置要给"行变列"的说明加一个 2×3 的例子；矩阵乘法维度规则要写明左边列数等于右边行数，并当场算 QK^T 的形状；缩放 √d_k 的方差推导要从期望和方差的定义一路推上来，不能直接给结论；log 的底要说明机器学习里默认是自然对数；下三角矩阵要配掩码的用途。

数学分析 18-20 章那边，求导四则法则和复合函数法则得先补，不然隐函数求导没法讲；中值定理要补，不然积分第一中值定理的证明接不上；部分分式要补，不然有理函数积分那类例子做不下去；arctan 要补，极坐标变换里的角度和狄利克雷积分都要用；叉积要补，空间曲线交线的切向量得分量交叉相乘；克莱姆法则要补，隐函数组的三个偏导公式靠它解出来；均值不等式和求根公式要补，条件极值的自拟题要用；微积分基本定理要给"面积函数的导数等于原函数"的直观，不然"求导和积分是逆运算"这句话没有落脚点。另外 ln 是什么、弧度制怎么换算、sgn 怎么读，这些初中没教但正文用到的，都现场解释。

数值例子还有两件事要注意。数据来源要写明，是真实数据还是随手假设只为演示计算，防止学习者把假设值当真实参数。例子得自洽，自己算一遍。教材里的例子也可能有错，数学分析某个隐函数例题给的验证点代入后不满足方程，照抄就教错了。算不通就改自拟题，正文里说明为什么换。

## 阶段 5：迭代

补完一轮，再按差生身份读一遍。合格的标志有三个：能独立推出全部公式，不需要翻前面的结论；能回答为什么这样设计，而不是只知道步骤；读不出新的卡点。

用户说"继续补"的时候，自己找下一批卡点，不要等用户指出来。人的耐心有限，能一次补完就不要留到下一次。

另一个实现上的迭代：产物会越来越大。内容超过三四百 KB 以后，单次写入容易超时或截断，改成骨架脚本加章节分批写入，最后合并。数学分析那份用了四个章节文件加一个合并脚本，改内容只改章节文件，重跑合并脚本，结果幂等。

## 阶段 6：自检与交付

先跑 `scripts/check_render.py`。它检查四件事：每个章节的 KaTeX 元素数量和残留 `$` 数量、章节内导航容器是否存在、移动端 viewport 下有没有横向溢出、折叠组件能不能点开。有残留 `$` 就去查公式里的裸 `<`，这是最常见的原因。

再跑 html skill 的 `scripts/shot.py`，出桌面和移动两张全页截图，看有没有截断、错位、空图。用户用手机时以移动截图为准。

关于 shot.py 的一个限制：`--eval` 和 `--eval-file` 只在 playwright 分支执行。环境里没有 playwright、退回 chrome CLI 时，eval 被静默跳过，不报错也没有痕迹。所以不要靠它验证"切换章节后公式有没有重新渲染"这类交互状态，会得到假阳性。替代办法是静态审查事件委托逻辑，确认绑定在 document 上能覆盖动态插入的元素，再配合全量 grep 核对每个章节的导航容器。

交付前过一遍 `references/checklist.md`，逐项打勾。

产物目录还要有一份 README.md，写给之后打开这个目录的人：产物是什么、怎么用、章节结构、怎么重新构建、自检怎么跑、已知的边界在哪。README 和 HTML 一起交付。

最后用 present_files 交单个 HTML，name 写文件名本身，不要另起标题。如果项目有源码脚本和抽取文本，连同 README 一起打包，用户可能要看过程。
